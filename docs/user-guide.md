# Посібник користувача

## Запуск

```
git clone https://github.com/Pazan121/UtilityBills.git
cd UtilityBills
dotnet run --project UtilityBills.App
```

Після запуску видно меню (число пунктів — шість плюс вихід). Дані лежать у теці `data` біля місця запуску:

```
1. Внести показник лічильника
2. Нарахувати платіж
3. Оплатити рахунок
4. Скасувати рахунок
5. Знайти рахунки
6. Звіт «нарахування за будинком»
0. Вихід
Пункт меню:
```

Числа з дробовою частиною вводьте **з крапкою** (`1250.5`), дати — як `рррр-мм-дд`.
Перший запуск створює демонстраційні показники абонентів 1 і 7: 1000 на 2026-09-01 і 1130 на 2026-10-01.

## Сценарій 1. Внести показник і нарахувати платіж (UC-01, UC-02)

```
Пункт меню: 1
Абонент (№): 1
Послуга (№): 1
Дата (рррр-мм-дд): 2026-11-01
Показник: 1250
Збережено показник 1250.00
Пункт меню: 2
Абонент (№): 1
Послуга (№): 1
[Лист для abonent1@example.com] Рахунок № 1: 330,00 грн
Рахунок 1, період 2026-11: 330.00 грн
```

Споживання 120 = 100 за 2,64 (264,00) + 20 за 3,30 (66,00) = 330,00 грн. У повідомленні абоненту роздільник береться з налаштувань системи (кома в українській локалі).

## Сценарій 2. Нарахування пільговику (UC-01, UC-02)

Ті самі дії для абонента 7 (він пільговик) дають 198,00 грн: перша сходинка за 1,32 грн (132,00) і друга за 3,30 грн (66,00).

## Сценарій 3. Оплатити й побачити відхилення (UC-03)

```
Пункт меню: 3
Рахунок (№): 1
Сума: 330
Оплату прийнято.
Пункт меню: 3
Рахунок (№): 1
Сума: 330
Відхилено: Стан Paid не дозволяє оплату
```

## Сценарій 4. Знайти рахунки й побачити звіт (UC-05, UC-06)

```
Пункт меню: 5
Абонент (№, Enter — будь-який): 1
Стан (Draft, Issued, Paid, Overdue, Cancelled):
№1, абонент 1, Paid, 330.00 грн
Знайдено: 1
Пункт меню: 6
Адреса будинку: Київ, вул. Вишнева, 1
Нарахування за будинком: Київ, вул. Вишнева, 1
Абонент 001: 330.00
Разом: 330.00 (1 рах.)
```

## Сценарій 5. Скасувати рахунок (UC-04)

Нарахуйте платіж абоненту 7 (сценарій 2), потім: пункт `4`, номер рахунку, причина `помилка в показниках` → «Рахунок скасовано.».

## Повідомлення про помилки

| Повідомлення | Що робити |
| --- | --- |
| Введіть ціле число більше 0. | Введіть номер цифрами |
| Введіть число з крапкою, не менше 0 (наприклад, 1130.5). | Використайте крапку, не кому |
| Введіть дату у форматі рррр-мм-дд. | Наприклад, 2026-11-01 |
| Невідомий пункт меню. | Оберіть цифру від 0 до 6 |
| Відхилено: Абонента N не знайдено | Перевірте номер (1–60) |
| Відхилено: Послугу N не знайдено | Існує лише послуга 1 |
| Відхилено: Дата показника не може бути в майбутньому | Введіть сьогоднішню чи ранішу дату |
| Відхилено: Дата має бути пізнішою за … | Внесіть показник пізнішої дати |
| Відхилено: Показник X менший за попередній Y | Лічильник не повертається назад: виправте значення |
| Відхилено: Для нарахування потрібні щонайменше два показники | Спочатку внесіть другий показник (сценарій 1) |
| Відхилено: Рахунок не містить жодного рядка | Споживання нульове: нарахувати нічого |
| Відхилено: Рахунок N не знайдено | Перевірте номер у меню «Знайти рахунки» |
| Відхилено: Стан … не дозволяє оплату / скасування | Подивіться стан у меню «Знайти рахунки» |
| Відхилено: Сплачено X, треба Y | Введіть суму не менше підсумку |
| Відхилено: Не вдалося прочитати / записати файл | Закрийте програму, що тримає файл у `data`, і повторіть |
| Внутрішня помилка. Подробиці — у data/app.log. | Збережіть `data/app.log` і повідомте автора |

## Де лежать дані й резервна копія

Усі файли — у теці `data`: `bills.json` (рахунки), `readings.json` (показники), `app.log` (журнал: час, рівень, сценарій, повідомлення).
Резервна копія — копіювання теки `data` у інше місце, коли застосунок закрито. Видалення `data/bills.json` і `data/readings.json` повертає початковий стан.
