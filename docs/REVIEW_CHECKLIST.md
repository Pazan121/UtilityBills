# Чекліст огляду коду

Тільки те, що не перевіряє машина (формат, імена за регістром, `error`-діагностики сюди не входять). Відмічають у pull request.

1. [ ] Рядок, що змінено, відноситься до однієї задачі: у зміні немає непов'язаних правок.
2. [ ] Імена беруться з глосарія: одне поняття — одне слово (`Subscriber`, не `Client`).
3. [ ] Метод-команда починається з дієслова, метод-запит називає результат; булеві члени — питання (`IsPrivileged`).
4. [ ] Назва тестового методу описує метод, умову й результат.
5. [ ] Змінна оголошена поруч із першим використанням; кожна змінна має один зміст.
6. [ ] У логіці немає магічних чисел і рядків: усі винесено в іменовані константи чи дані.
7. [ ] Стани й види — перелічення, а не рядки чи числа.
8. [ ] Публічні колекції віддаються як `IReadOnlyList`, а не `List`.
9. [ ] У зміні немає закоментованого коду й мертвих методів.
10. [ ] Коментарі пояснюють «чому»; жоден не повторює код і не застарів.
11. [ ] Усі `TODO` мають формат `TODO(UB-NN)` і номер завдання існує в трекері.
12. [ ] Гроші, тарифи й обсяги — `decimal`; суми округлено за правилом D-14 / X-04.
13. [ ] Дати й час — `DateOnly`/`DateTimeOffset`; годинник у логіку передається параметром.
14. [ ] Нову поведінку покрито тестами; тест перевіряє результат, а не лише виконання рядка.
15. [ ] Глибина вкладеності, цикломатична складність, довжина методу й кількість параметрів не перевищують зупинні межі розділу 5.2; перевищення попереджувальних меж пояснено.
16. [ ] Публічні методи перевіряють аргументи на початку; помилки подано винятком, а не значенням `-1` чи `null`; метод або запит, або команда.
17. [ ] Правила в зміні не ослаблено без запису в журналі рішень.
18. [ ] Кожне придушення правила має причину (коментар чи `Justification`).

_Стандарт v1.0.0._
