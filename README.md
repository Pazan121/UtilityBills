# UtilityBills

![CI](https://github.com/Pazan121/UtilityBills/actions/workflows/ci.yml/badge.svg)

Консольний застосунок обліку показників лічильників і нарахування комунальних платежів за сходинками тарифу.

**Варіант № 14. Римарцов Володимир, група 471. Дисципліна «Конструювання програмного забезпечення».**

## Швидкий старт

```
git clone https://github.com/Pazan121/UtilityBills.git
dotnet build UtilityBills
dotnet run --project UtilityBills/UtilityBills.App
```

## Структура рішення

- `UtilityBills.Core` — бібліотека: домен, прикладний шар (сервіси, правила, звіти) та інфраструктура (JSON, журнал, годинник).
- `UtilityBills.App` — консольне меню та композиційний корінь.
- `UtilityBills.Tests` — модульні тести (xUnit).
- `docs/` — специфікація, архітектура, посібник користувача, журнал рішень, самооцінка.

## Можливості

Сценарії докладно описано в [docs/spec.md](docs/spec.md):
UC-01 внести показник лічильника · UC-02 нарахувати платіж · UC-03 оплатити рахунок · UC-04 скасувати рахунок · UC-05 знайти рахунки · UC-06 звіт «нарахування за будинком».

## Тести та покриття

```
dotnet test --collect:"XPlat Code Coverage" --settings coverlet.runsettings
```

Поточне рядкове покриття бібліотеки логіки (домен і прикладний шар): 96 % (межу вимірювання задано в `coverlet.runsettings`). Усю перевірку, яку робить CI.

## Технології

.NET 8, C# 12, xUnit, coverlet, аналізатори Roslyn та StyleCop, GitHub Actions.

## Обмеження й відомий борг

- Облік лише однієї послуги (електроенергія) з єдиною шкалою тарифу; тарифи зашито в код.
- Немає бази даних, ролей користувачів і графічного інтерфейсу; дані зберігаються у файлах JSON у теці `data`.
- Меню не покрито автоматичними тестами (перевірено вручну за `docs/user-guide.md`).
- Правило залежностей між шарами охороняє архітектурний тест, а не компілятор.
