# CODING_STANDARD.md
## 1. Загальні положення
Стандарт застосовується до всіх файлів C# у UtilityBills.Core та UtilityBills.App.
Код має збиратися командою `dotnet build` без попереджень.
## 2. Іменування
| Сутність | Конвенція | Приклад | Антиприклад |
|---|---|---|---|
| Клас, запис | PascalCase, іменник | UtilityBillLine | utilitybillline |
| Інтерфейс | I + PascalCase | IUtilityBillRepository | Repository |
| Метод | PascalCase, дієслово | CalculateTotal | calc |
| Властивість | PascalCase, іменник | BillingPeriod | GetBillingPeriod |

## 3. Форматування
1. Відступ — 4 пробіли; табуляція заборонена.
2. Довжина рядка — не більше 100 символів.
3. Фігурні дужки — стиль Allman; дужки обов’язкові навіть для однієї інструкції if.
4. Між членами класу — один порожній рядок.
5. using розміщуються на початку файлу; системні директиви — першими; невживані видаляються.
6. Простір імен — файлового рівня: `namespace X;`.
## 4. Коментарі та документація
Коментар має пояснювати причину рішення, а не повторювати код.
Публічні члени бібліотеки документуються XML-коментарями, коли цього вимагає етап роботи.
Погано:
```csharp
// збільшуємо лічильник на одиницю
count = count + 1;
```
Добре:
```csharp
// Склад округлює вагу вгору, тому й тут Ceiling.
weight = Math.Ceiling(rawWeight);
```
## 5. Структура проєкту
`UtilityBills.Core/Domain` містить сутності предметної області.
`UtilityBills.App` містить точку входу та демонстраційний сценарій.
Бібліотека Core не повинна залежати від консольного введення/виведення.
Кожен публічний доменний тип зберігається у файлі з відповідною назвою.
## 6. Правила комітів
Повідомлення коміту мають формат `тип: короткий опис`.
`feat` використовується для нової функціональності, `fix` — для виправлення,
`docs` — для документації, `chore` — для інфраструктурних змін.
Один коміт має містити одну завершену логічну зміну.
Перед комітом перевіряються збірка та статус Git.
